# 研究报告 01：对话界面与「AI 工具调用整个循环」的 UI

> 对标对象：ZCode v3.17.1（D:\ZCode，a60ba6a7）`packages/ui/src/v4/`
> 调研日期：2026-11-01 · 用途：ClerkBox（CB）对话界面重构的施工图纸
> **这是全部研究报告中最优先的一份。**

---

## 0. TL;DR

ZCode 对话界面的「专业感」**全部来自机制，而不是配色和间距**。它的核心判断是：UI 是一份**只读投影**，不产生任何会话事实；渲染性能靠「turn 级虚拟化 + 冻结历史分区 + live tail 出虚拟行」三板斧；交互手感靠「滚动权状态机 + 工具卡折叠状态机 + renderer 注册表」三个状态机。

CB 的现状：**机制模块已抄了 6 件（模块级完成度 ~90%），但集成完成度只有 ~30%**——shiki 高亮器写完了没通电，timeline 三件（行高缓存/滚动锚定/live-tail 拆分）写完+测试完但没接进 MessageList。**CB 的差距不在「不知道怎么抄」，而在「最后接线」。**

## 1. 总体架构：协议 v4 订阅投影

```
Agent 核心（事件唯一事实源，约 70 种 SessionEventType）
    │ appendEvent → eventStore.append（seq 唯一来源）
    │            → persistDurableSessionEvent（映射 SQLite message/part 行）
    │            → notifyEventSinks
    ▼
v4 网关（bootstrap/src/zcode-protocol-v4/）→ ConversationTopicPublisher
    │ 按 topic conversation/<sessionId> 推帧：snapshot + delta
    ▼
UI 投影 store（packages/ui/src/v4/conversationProjectionStore.ts，1654 行）
    ▼
渲染单元构建（v4/conversationTurnRenderUnits.ts，756 行）
    ▼
虚拟时间线（v4/ConversationTimeline.tsx，2325 行）
```

**投影 store 的三条铁律**（写在 `conversationProjectionStore.ts` 文件头）：
1. snapshot 到达 → **整体替换，绝不 merge**；
2. delta 帧仅在 `frame.fromSeq === snapshot.seq` 时 apply，**断档不猜**——由服务端裁决 resume 还是重发 snapshot；
3. 断档时状态未被污染，携当前水位重订阅。

其他关键机制：
- **行结构共享池** `v4/conversationRowSharing.ts`：snapshot/delta 行按值相等换回池中旧引用，防止闭包链持有上百份大字符串。
- **「冻结历史 + 尾轮」分区**（`getConversationRowsPartition` + `memoizeByRows`，L287-384）：WeakMap 以 rows 数组引用为键，流式帧只改尾轮时 history 段引用不变，下游派生成本 O(delta + 尾轮)。实测修复：「8000 行会话每帧 1.75ms → 0」。
- **乐观 overlay 对账**：发送命令 → `pendingCommandRegistry` 登记 → ACK 对账；另有 watchdog——ACK 后 2s 内必须在投影里看到 user row，否则触发 recovery。
- **Delivery Profile**：`continuous`（桌面，30ms flush，全量流式）与 `replayable`（Web/远控，150ms flush，只流 text）。

> **CB 借鉴**：CB 的 `agent-reducer.ts`（纯函数 StorePatch）+ `agent-event-apply.ts`（幂等应用）已经是同构思路。缺的是「冻结历史分区」和「断档不猜」的严格性——CB 事件带单调 seq + 溢出 resync，方向对，但流式重渲时历史行引用会变，导致虚拟列表整树重算。

## 2. 行数据模型：渲染任一行不需看别的行

`packages/shared/src/zcode-protocol-v4/rows.ts` —— `ConversationRow` 判别联合：
`turnHeader | userInput | assistantText | reasoning | toolCall | artifact | subagent | hookInvocation | timelineMarker`

行基座字段：`rowId`（session 内单调、永不复用）、`turnId`（**turn 是 row 上的标签，不是容器**）、`entityId`、`createdAt/createdAtSeq`、`actions`（canFork/canEdit/canRetry/canRewindFiles/editDisposition）。

**ToolCallRow**（rows.ts:206-235）——CB 对标的重点，6 态状态机：

```
status: "inputStreaming" | "pendingApproval" | "running" | "success" | "error" | "cancelled"
```

| 字段 | 作用 |
|---|---|
| `inputText` | 流式参数原文（打字机效果的数据源） |
| `input` | 完整参数（可选，到齐才有） |
| `output` | `{text, display, truncated}` + `outputPreview`（Bash 有界内容） |
| `error` | `{code, message}`，status=error 必带 |
| `display` | **工具自报的结构化展示事实**（解析失败只丢卡不拒帧，`.catch(undefined)`） |
| `approvalInteractionId` | pendingApproval 时指向 pendingInteractions 项 |
| `progress` | MCP 进度，终态清除 |
| `backgrounded/workId` | 转后台关联 |

**协议限额**（`core.ts` PROTOCOL_V4_LIMITS）：snapshot 尾窗 60 行、range 上限 200 行、工具输出 final head/tail 各 32KB、帧 1MB。

> **CB 借鉴**：CB 的工具结果是单轨 `Promise<string>`，UI 靠 `__EDIT_DIFF__` 尾巴 JSON 旁路拿展示数据。ZCode 的 `display`（工具自报展示事实）+ `outputPreview`（有界预览）+ 32KB head/tail 截断 + 按需拉全量（`onLoadFullToolCallFields`）是 CB 工具结果双轨化的现成模板。

## 3. rows → 渲染单元：turn 是虚拟化的 key

`v4/conversationTurnRenderUnits.ts`：`buildConversationTurnRenderUnits(rows)` 按 `turnId` 分组 → materialize → 归一化。**虚拟列表 key = turnId**——「key 只依赖协议稳定的 turnId，否则补页会把原 turn 当新节点重挂、丢测高缓存」。

`ConversationTurnRenderUnit` 字段（节选）：`key/turnId/header/visibleUserInputs/assistantWorkRows/assistantHistoryRows/assistantFollowingRows/assistantTailRows/assistantTextRows/flowItems/workSegments/isLastTurn/isRunning/workflowLaunch`。

隐藏规则（值得抄的细节）：
- `DeferredToolCall` + inputStreaming 隐藏（参数没到齐没有身份，渲染会闪）；
- 空 reasoning 终态块隐藏；
- turnHeader 是权威轮次边界，**终态主轮不能被同轮 background tool 重新推成 running**（`resolveTurnRunning`）。

**Agent 工具行 ↔ 子代理行配对**（`v4/conversationAssistantWorkItems.ts` `pairSubagentRows`）：按 `parentToolCallId` **精确配对**——并发 spawn 的 SubagentSpawned 事件异步到达，FIFO 配对会张冠李戴。CB 的 SubAgentCard 目前是占位+通知条，这个配对键是重构时的关键。

**工作分组**（连续同类工具 ≥2 才升级为父分组卡，单个保持原工具语义）：
- `exploreGroup` / `executeGroup` / `changesGroup`（默认关）/ CUA 组；
- 分组 key **锚定首行**（`explore:${首行rowId}`）而非末行——流式追加时保住展开状态；
- 段状态 `resolveGroupStageStatus`：段尾在跑 = in_progress，否则看有无 cancelled。

## 4. 工具卡渲染基座（ToolCallBlocks，CB 最该抄的部分）

**入口适配**：`v4/toolCallRowAdapter.ts` `toolCallRowToLegacyNode(row)` 纯函数——v4 状态映射到旧渲染词表（`running→in_progress, success→completed, error→failed, cancelled→stopped`）；`input` 缺席时用 `buildZCodeStreamingToolInputPreview(inputText)` **还原流式半截参数 JSON**（打字机期间也能渲染出可读的参数预览）。

**`ToolCallBlocks.tsx`（411 行）四件事**：
1. **入场动画一次性记账**：模块级 `toolEntranceAnimationKeys: Map<string, number>`（上限 800，LRU 修剪）——任务切换/虚拟重挂不重播淡入动画；
2. 构造统一渲染上下文 `ToolCallBlockRenderContext`（约 30 字段：statusLabel/errorText/isRunning/...）；
3. **renderer 三层分流**（`resolveRenderer.ts`）：
   - 第一层：分组 kind（changesGroup/executeGroup/cuaGroup）；
   - 第二层：**按工具名精确认领**（ToolSearch/SaveWorkflow/GetWorkflowRun/…——v4 新工具刻意排在 family 之前，因为 identity 解析为 unknown 会掉进兜底卡）；
   - 第三层：`identity.family`（`lib/toolIdentity.ts`）：file-read/file-write/explore/switch-mode/web-fetch/search/shell/goal/... → 都不认识才 `FallbackToolCallBlock`（raw JSON 兜底）。
4. 容器带 `data-testid / data-tool-call-id / data-tool-name / data-status`（E2E 锚点）。

**`ToolLayout.tsx`（363 行）折叠状态机**——这是工具卡手感的灵魂：
- **展开状态持久 = 模块级 `toolLayoutOpenState: Map<string, boolean>`**（键 `persistOpenKey ?? toolId`）——虚拟列表重挂、turn 重渲都不丢用户的手动展开；
- `autoOpen`：一次性 effect，首次满足条件自动展开（如 edit/read 完成后），此后用户手动收起生效；
- `autoCollapseOnComplete`：只在 `running → !isRunning` **边沿**收起一次——子代理跑完不会把长明细永久摊开；
- **300ms 延迟卸载**（`TOOL_CONTENT_COLLAPSE_UNMOUNT_DELAY_MS=300`）：收起时不立刻卸 children——Radix 折叠动画要读 `--radix-collapsible-content-height`，子内容先卸会继承外层高度变量、撑出超高空白块。padding 挂内层 div 而非动画节点（否则归零后有 8px 残留）；
- **失败态不强制展开**：错误详情挂到状态词的 Tooltip（可复制，1.5s 重置），`decoration-dotted underline-offset-2`；
- 运行态 kind 文案用 `animated-gradient-text` 扫光，**图标保持静态**（"旋转 loading 会让动画长期占用渲染资源"）。

**`ToolSummaryRow.tsx`（235 行）折叠摘要行**：图标 + kindLabel + kindDetail + 来源 badge（子代理来源，窄容器 `@max-[360px]` 隐藏）+ primary/secondary text + diffCount + statusNode。注意两个 a11y 细节：整行是 button 时要手工补 Enter/Space；用 Radix CollapsibleTrigger 时 trigger 是 div 而非满宽 button（否则吞掉摘要内嵌文件预览按钮的点击）。Chevron `rotate-90` + `opacity-0→group-hover:opacity-100`。

**展开体**（`ToolCallBody.tsx`）：inlinePreview（text→`max-h-60 overflow-auto` 包 CodeBlock；markdown 走 MessageResponse；image→异步读取预览）+ ToolInput（JSON 参数，max-h-60）+ ToolOutput。**失败态只渲染 errorText**（"一边报错一边渲染 JSON 会被参数淹没"），容器 `bg-destructive/10`。

**diff 展示**（`renderers/EditInlineDiffContent.tsx`）：**首帧只渲染轻量 hunk 文本，effect 异步补 Shiki token**——"@pierre/diffs 直接挂载会把高亮+Shadow DOM 汇总压到主线程，点击展开掉帧"。diffCount 用 `FlipMetricValue` 一次短翻页动画 + `text-diff-added/removed`。

**长输出**：协议 32KB head/tail 截断 + `onLoadFullToolCallFields(toolId)` 按需拉全量。

## 5. 审批/权限请求 UI（配合报告 04）

- **数据**：`snapshot.pendingInteractions`，`PendingInteraction = { interactionId, kind: "permission"|"userInput"|..., anchorRowId, autoResolution?, payload }`。payload 里有 `options[]`（`allowOnce|allowAlways|deny|custom`）和 `fullAccessOption`。
- **形态：模态对话框**（不是时间线内联卡片）。时间线上的工具行仍渲染成 `pendingApproval` 状态的待执行卡，弹窗是唯一决策入口。
- **`PermissionDialog.tsx`（1121 行）核心设计**：
  - 预览块按工具分型（edit=文件 diff / execute=命令 / mcp / web-fetch / skill / workflow / fallback），**直接复用工具 renderer 渲染审批预览**（`forceOpen`）——审批窗里看到的就是执行后卡片的样子，零额外预览代码；
  - 选项 = **numbered listbox**（`role="listbox"`）：`1. 允许一次 / 2. 本项目始终允许（附 prefix 规则说明）/ 3. 拒绝 / 4. 反馈（自由文本，4096 上限）`；键盘上下选择、双击激活；`data-permission-option-kind` 供 E2E；
  - 按 `key={interactionId}` 重建弹窗（修过的 bug：连续 permission 复用弹窗会带脏输入焦点）；
  - `InteractionRequestOriginBadge` 显示来源（**子代理申请 ≠ 主 agent**，路由回父会话并标注是谁在问）。
- `autoResolution` 三形态：`hiddenGrace | visibleCountdown（AskUserQuestion 自动结束倒计时）| snoozed`。

> CB 已有 `PermissionCard.tsx`（420 行，编号三选项 listbox、键盘 1/2/3）——骨架已同构。差距：CB 预览靠 `permission-preview.ts` 独立实现，ZCode 是复用工具 renderer；CB 的 ask 选项没有「总是允许（项目级持久规则）」（见报告 04）。

## 6. 消息行体系与 live tail

- **行级分发**：`v4/ConversationRowView.tsx` 按 `row.kind` switch 分发到 `ConversationUserInputBubble`（epilogue 引擎附加文本默认收起）/ `assistantText`（MessageResponse markdown + 点赞点踩）/ `reasoning`（独立行；「关闭完整思考时仍显示第一条」`messageStreamFirstReasoningRowId`）/ toolCall / subagent / artifact / timelineMarker。
- **轮级组装**：`v4/ConversationTurnGroup.tsx`（1729 行）：统一 `flex flex-col gap-4` 组容器；`TurnChatLoadingSlot`（ChatLoading 带 elapsed 秒数）；「已工作」折叠组（workSegments 视觉段）。
- **ChatLoading 显隐规则**（`v4/chatLoadingVisibility.ts`）：仅最后轮且 running 才显示；被 permission/AskUserQuestion 交互阻塞时不显示（弹窗已是唯一进度反馈）；行级 fallback 防恢复期 loading 闪回。
- **live tail**（`v4/conversationTimelineLiveTail.ts`）：只把**最后一个 running turn** 拆成普通文档流（不放虚拟行）——「正文 DOM 先长高、ResizeObserver 下一帧才回填 totalSize，虚拟行里轮尾 loading 会来回跳」；历史/陈旧 running 行仍归虚拟列表。
- **流式 markdown 双模式**（`components/ai-elements/message.tsx`，1756 行）：
  - `resolveMessageStreamdownMode(renderStreaming)`：只有真实流式走 `streaming`，历史/完成态固定 `static`——生产级 React #185 修复（完成态长消息走 streaming 分块缓存会在历史 markdown 上反复同步状态）；
  - **流式期间关代码高亮 + 关 mermaid**（`enableSyntaxHighlighting={!renderStreaming}`）；完成后 shiki 双主题（light/dark 媒体查询）；
  - CJK 扩展：`@streamdown/cjk` 删除线 + remark-gfm 同时关 singleTilde（否则 `~text~` 语义冲突）；`createMathPlugin({singleDollarTextMath:true})` 兼容 `$...$` 行内公式；
  - 本地文件链接先过自定义 rehype 插件规整（Windows 盘符 `C:` 会被 rehype-harden 拦成 `[blocked]`，裸文件名补 `./`）；
  - `MessageResponseMarkdownBoundary`：单条 markdown 渲染异常降级纯文本，不冒泡到会话区。

## 7. 时间线基础设施（性能三板斧）

**`v4/ConversationTimeline.tsx`（2325 行）**：
- `@tanstack/react-virtual` turn 级虚拟化，**overscan=2**（⚠ 不是老结论的 8——「前后各 8 轮会在搜索跳转时同步挂载大量屏外 Markdown」）；
- `estimateSize`：测高缓存命中用测量值，未测量 turn 级单元回落**一屏 clientHeight**（⚠ 不是 72px——72px 会首屏挂十几轮正文；72px 只作小行兜底），`measureElement` 写回缓存；
- `shouldAdjustScrollPositionOnItemSizeChange` 接自定义策略：following 中/宽度变化中/前插批次中一律不补偿。

**滚动状态机**（`v4/timelineScrollAnchor.ts`，306 行纯函数）：
- `following` 表达**用户滚动权**而非几何快照；
- **capture 阶段意图捕获**（wheel/touch/键盘，早于 scroll 事件），`USER_SCROLL_INTENT_TTL_MS=1200`；
- 捕获到 awayFromBottom **当帧立即 `commitFollowing(false)`**——抢在终态 layout effect 前，否则过期 following=true 会把用户拽回底部；
- `reconcileFollowingForContentAnchor` 对账：明确上滚→解除；无输入→保持；未知→按落点+2px 容差判定；
- **loadOlder 前插锚定**：`prependScrollAdjustment`（scrollTop' = scrollTop + ΔtotalSize，仅真前插）+ 提前 2 个视口预取。

**测高缓存**（`v4/timelineRowHeightCache.ts`，61 行）：Map 键=turnId，**LRU 4000**（delete+set 刷新顺序），会话切换 `clear()`。对抗「流式行长高→virtualizer 重建→缓存清回 estimate→滚动条跳」。

**ConversationStatusPanel**（2228 行）：会话右上角状态面板——Git 分支/变更、Goal 摘要、计划、后台 bash（可暂停/取消）、运行中子代理、workflow runs。收起态摘要+展开态分区，两形态内容优先级一致（同一 model 函数维护）。

## 10. 设计规范（DESIGN.md + token 体系）

`D:\ZCode\DESIGN.md`（655 行）是**给编码 agent 用的最高优先级约束文档**：
