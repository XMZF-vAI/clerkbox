# 研究报告 02：动态工作流（dynamic-workflow）

> 对标对象：ZCode v3.17.1 `packages/dynamic-workflow`、`packages/dynamic-workflow-runtime`、`apps/zcode-cli/packages/bootstrap/src/app/dynamic-workflow-*.ts`、`docs/dynamic-workflow/`（5 份 spec 共 8663 行）
> 调研日期：2026-11-01 · 用途：ClerkBox 实现同款「脚本化多子代理工作流」
> 背景输入：鱼皮文章《又一个国产版 Codex 神器，也来卷办公了！》——380 篇教程体检任务：105 个子代理、4000 万 token、6 阶段分工、流程图确认、Excel 交付、可复跑。

---

## 0. TL;DR

ZCode 的动态工作流本质是：**AI 先把「怎么干」写成一份 TypeScript 脚本（SOP），编译器静态分析出因果图给用户确认，确认后由一个确定性引擎调度一支持久子代理小队照脚本干活；journal 重放让 run 可以暂停/恢复/修订（Amend）而已完成步骤零 token 重算；额度用尽自动等 resetAt 续跑。**

仓库里其实有**三代** workflow 机制（一代脚本 DSL → 二代 expert 图调度 → 三代 dynamic-workflow），鱼皮测到的是三代。给 CB 的最小实现清单见 §9——核心资产是「facade 声明 + 一个 ts.Program 同时产出诊断/站点表/JSON Schema/lowered 代码」这一件事。

## 1. 用户体验全链路（鱼皮文章逐条对照实现）

| 鱼皮看到的 | 底层实现 |

| AI 加载 dynamic-workflows 技能 | 技能门（428）：四个创作工具在 `resolveInput` 检查「模型可见历史里有没有一次成功的 Skill(dynamic-workflows)」，没加载直接拒 |

| 写链接检测脚本试跑、`EvalWorkflowSnippet` 提前验证分组 | EvalWorkflowSnippet：scratch facade（编译期排除 agent/report/artifact/hole）+ 同一套编译器/沙箱 + InMemoryJournalStore，完全瞬态（`dwfeval-` runId），`world.run` 仍需用户确认 |
| 写好流程图等确认再跑 | CreateWorkflow `prepareApproval`：**编不过不弹窗直接回诊断**；编过 → `gate:"ask"` + display（causalityGraph）→ `WorkflowPermissionBlock` 渲染逐相位站点时间线 |
| 105 个子代理分工干活 | 每 actor 一个持久 child AgentRuntime（完整工作工具集减去禁用表），每次 ask 一个 turn |
| 哪些 AI 员工在干活一目了然 | roster：事件+节点行+actor 行纯函数派生「phase 表/花名册/健康面」，UI 单时钟 reducer 无轮询 |
| 消耗 4000 万 token | `spent_tokens` 记在 `dwf_run` 表 |
| 问题清单写进 Excel | actor 写文件 + `report()/artifact()` 发布产物，终态通知带回 artifacts |
| 保存下来下次复跑 | SaveWorkflow → `<cwd>/.zcode/workflows/<name>.dwf.ts`（YAML 前言+脚本正文，project/global 两个 scope） |
| 被限流卡了一阵子 | 模型失败策略：限流=瞬态 → 无上限退避重驱（2s→60s 抖动、Retry-After 优先）；quota cap → 整 run `stopped(provider)` → **quota-resume：resetAt+60s 自动续跑** |

## 2. 工具面（11 个工具 + 灰度门）

**名单**（`core/src/tool/handlers/index.ts` DYNAMIC_WORKFLOW_TOOL_NAMES）：
`CreateWorkflow, AmendWorkflow, SaveWorkflow, ListSavedWorkflows, ListModels, EvalWorkflowSnippet, ListWorkflowRuns, GetWorkflowRun, ResumeWorkflowRun, ResolveWorkflowQuestion, FillWorkflowHole`

关键契约细节：
- **CreateWorkflow**（contracts/src/tools/create-workflow.ts，617 行）：三来源 `script|saved|path` 恰好一个——XOR **刻意不写在 schema 上**，由 `validateInput` 强制（归一化后 `script+saved` 同时在场是合法执行态）；`max_concurrency`、`subagent_model`（每子代理模型需用户点名）；输出含 `causalityGraph`（steps/lanes/participants/handoffs/phases/holes，全部限长常量）、`status:"backgrounded"`、`backgroundTaskId≡runId`；结果文案**显式劝阻 TaskOutput 轮询**（完成会主动通知）。
- **按需激活**：会话出生不带这批工具；`/workflow` 命令、恢复带工作流历史的会话等触发 `activateDynamicWorkflowTools` 再注册（冷恢复按 entry 或全量历史扫描 `/^\/workflow(?:\s|$)/i` 补判）。
- **Agent 工具描述联动**：灰度开 → Agent 描述里加「user explicitly asks for a workflow → CreateWorkflow is mandatory: do not use this tool instead, however small the task」；灰度关 → 该行删除。**工具面与描述永不漂移。**

## 3. 脚本模型：编译、沙箱、agent()、并发、hole、journal

### 3.1 编译（compile-once，全系统最独特的资产）
`packages/dynamic-workflow/src/compiler/compile.ts` + `facade/dts.ts`：
- 一份 `.d.ts` 环境声明定义脚本可用的全部 API（`agent/ask/files/git/world.run/phase/hole/report/artifact/channel/future/args/run/log`）；
- **一个 ts.Program 同时产出四样东西**：①诊断（strict、无 import/export、`world.run` 命令名/phase 名必须是字面量、fan-out 回调里禁固定名 `agent()` 与 `hole()`）；②站点表（每个要等待的 facade 操作 = 一个站点，如 `ask#3`、`hole#21b40fca`）；③每 ask 站点的结果 JSON Schema（从 TS 接口+JSDoc 合成）；④lowered async 函数体（降级成自由标识符仅 `__host` 的函数）。
- 因果图（`src/analysis/`，60+ 文件，可先砍到 sites/phases/fanout-cardinality/hole 四件）从站点表派生：steps/lanes/participants/phases/phaseEdges/holes + 限长投影 → **确认窗与 handler 读同一份分析，中间没有模型调用**。

### 3.2 沙箱执行（进程隔离，不是安全沙箱）
`dynamic-workflow-runtime/src/harness.ts`（644 行）：
- lowered 体+args 内嵌写入 `<cwd>/.zcode/workflow-runs/<runId>.mjs`，`spawn(node)`；
- 子进程 vm context 里建 `__host`，NDJSON 桥接；终结失败（脚本抛错/子进程崩溃/墙钟超时/行解析失败）→ `engine.fail()`；
- `AbortSignal` 是唯一真取消。

### 3.3 确定性引擎（journal 决策）
`src/engine/engine.ts`（693 行）+ `scheduler.ts`（555 行）：**核心零 I/O、零时钟、零随机**。
- 实例身份 = 站点id×序号（`ask#3@n`）；
- 每次 host 调用先查 journal 的 `(siteId, ordinal)`——**命中即短路（零 driver 调用）**，防御性校验 `inputHash`，不一致 → 整个 run 大声失败；
- 每 actor FIFO（串行 actor = 共享上下文即串行化）；
- ask 三值裁决：`accept / reject-repair（预算内同 turn 重试）/ nudge（新 turn）`。

### 3.4 agent() 派发（driver）
`bootstrap/src/app/workflow-driver.ts`：
- 每个 actor 一个**持久** child AgentRuntime（重复 executeTurn 累积 messageHistory），每次 ask 一次 turn；
- typed 结果经 `submit_result` 工具 + port 阻塞应答；
- actor 工具面 = 完整工作集 **减去** `ACTOR_DISALLOWED_TOOLS`（AskUserQuestion、plan 两件套、CreateWorkflow/AmendWorkflow、ReadSessionContext、ResolveWorkflowQuestion）——**子代理不问人**（用 `escalate` 把问题铸成 `dwfq-` qid 停驻，主代理经 ResolveWorkflowQuestion 作答后 actor 就地继续）；
- 世界读取（files/glob/grep/git）超限**拒绝不截断**；产物发布进 ToolArtifactStorePort（`zcode-artifact://<session>/<id>`）。

### 3.5 并发（三层）
- 引擎 `caps`（run 上界，`setMaxConcurrency` 就地生效 = retune）；
- 进程级 AIMD 治理器：每 `${provider}/${model}` 一个桶，**每次模型请求一张 ticket**（退避 sleep 不持槽）；
- 座位闸门：超界子代理跑完手上请求后于下一个 turn step 停驻（会话/转录不丢），`activeAsks = working + parked` 算术保证不死锁；
- 默认并发 `clamp(4, 16, availableParallelism() - RESERVED_PARALLELISM)`。

### 3.6 hole（空洞/人工介入点）
- 脚本 `await hole<T>(name, prompt)` 到达未补洞 → 该分支停驻，**run 其余部分照跑**；
- `FillWorkflowHole(run_id, hole_id, script|path)`：把**仅语句**编译进洞位 → 草稿被重写成「有效脚本」（resume/amend/save 都以它为准）；
- 三形态：中途洞 / 尾部洞（`return await hole(...)` 链式生长）/ 带默认体洞；fan-out 回调内禁洞。

### 3.7 journal 重放与缓存
- 重放（`engine-resume.ts`）：读 work 行（不带结果）+ artifact 行 → 按事件恢复**结算次序闸** → `seedRecordedAsks` → 恢复产物版本与 report 计数（count(*)+字节和，一条不读进内存）；
- Amend 导入缓存（`imported-cache.ts`）：按**有效名+规范化 persona** 匹配 actor；ask 按**字节相同的指令**依序匹配，命中零 token 结算；**活子代理首次写工作区或 world.run 执行后缓存关闭**——世界已变的缓存不可信。

## 4. 生命周期与状态机

```
RunStatus = "pending" | "running" | "completed" | "errored" | "stopped"
RunStopReason = "user" | "model" | "provider" | "interrupted" | "superseded"
```

- `errored`（脚本自身失败）**不可 resume**（重放同错），必须 AmendWorkflow 改脚本；`stopped` 一律可 resume，**除 `superseded`**（拒绝并给出后继 runId）。
- **模型失败策略**（runner 与 driver 读同一张表）：
  - `stop`（确定性：登录过期/模型不在套餐/quota cap）→ 整 run `stopped(provider)` 携 `resetAt`；
  - `context_exceeded` → 节点以 ContextLimit 失败（**脚本可 catch**）；
  - `retry`（瞬态：限流/过载/网络）→ 无上限退避重驱；**模型侧错误永不进脚本**——SKILL.md 明令不写重试循环；run 级 stall 时钟（20 分钟一条通知）让人知道它在等。
- **quota-resume**（`dynamic-workflow-quota-resume.ts`，283 行）：`stopped(provider)+quota+resetAt` → `resetAt+60s` 自动 resume；唯一数据源是 journal run 行（到点重读、resetAt 未变才续）；**不循环**；多次续跑间隔 10min 起逐次翻倍封顶 1h。背景：22 个撞额度的 run 里 17 个靠手动恢复——实测数据驱动的功能。
- **Amend/supersede**：前驱在飞 → `abort({superseded})` 并 **await 它自己的结算 promise** → 新 run 带 importedCache+resumedFrom 启动；只带 `run_id+max_concurrency` 且前驱在跑 → **就地 retune**（无新 run）。
- **App close**：service 以 `interrupted` abort 全部在飞条目并等结算，**引擎自己写终态行**（dwf_run 单一写入者原则）。
- **通知闭环**：终态经 runtime task registry 入队 `<task-notification>`——**errored/stopped 也带回已产出结果**（report() 打捞），显式劝阻轮询。

## 7. 与普通子代理（Agent/Task）的关系

- **显式点名才启动、点名即绑定**（SKILL.md §1 裁决表）：用户说「用 workflow」哪怕一行回复能答也要走 workflow；单次委派归 Agent。
- workflow actor 的权限模式**在建 run 那一刻定死**、记入 run-launched 事件；**会话此后换模式不影响在飞 run**。
- 工具面减法是**双列**的（bootstrap 的 `ACTOR_DISALLOWED_TOOLS` + core 的 `WORKFLOW_CHILD_DISALLOWED_TOOLS`）——因为 CreateWorkflow 是 alwaysAsk，子 yolo runtime 里无窗可弹。
- 灰度门四件事（工具面减法/技能减法/`/`命令目录减法/`/workflow` 展开减法），fail-closed 缺省。

## 9. 给 CB 的最小实现清单（按依赖顺序）

CB 现状（盘点结论）：编排原语已齐（真并行 spawn、后台+通知、steering、续跑、schema 级裁剪、单取消、subagent-control 注册表），**缺整个工作流层**；「单轨 string 工具契约」是结构上最需先松动的约束。

1. **工具结果双轨先行**（依赖报告 05 P0）：typed 结果无处安放则一切免谈。
2. **facade dts + 编译器**：一份 `.d.ts`（agent/ask/files/git/world.run/phase/hole/report/artifact/args/run/log）+ 一个 ts.Program 产出诊断/站点表/ask JSON Schema/lowered 体。CB 是 Electron，可以直接用 typescript 包（主进程已具备 Node 环境）。
3. **静态分析→因果图**（先砍到 sites/phases/fanout/hole 四件）→ 直接喂确认窗。
4. **确定性引擎**（站点×序号身份、journal 短路+inputHash 校验、每 actor FIFO、hole 停驻表）。先内存 journal。
5. **沙箱子进程**：`node:vm` context + `__host` NDJSON RPC + 入口文件落盘 `.clerkbox/workflow-runs/`。明示「进程隔离不是安全沙箱」。
6. **driver**：每 actor 一个持久子会话（CB 的 runSubAgentLoop 后台模式已支持续跑，正好复用）；ask 三值裁决经 `submit_result` 工具；escalate 铸 qid。
7. **journal 存储**：CB 的 clerkbox.db 加 `dwf_*` 四表 + 重放。
8. **生命周期**：五态+五 stopReason；失败策略表+无上限退避+stall 时钟；quota 自动续跑（resetAt+60s、不循环、间隔翻倍）。
9. **工具面+技能门**：CreateWorkflow（三来源 XOR、prepareApproval=编译图弹窗、alwaysAsk）、AmendWorkflow、FillWorkflowHole（splice+有效脚本回写）、SaveWorkflow/ListSavedWorkflows（`.clerkbox/workflows/*.dwf.ts`）、EvalWorkflowSnippet、Get/ListWorkflowRuns、ResumeWorkflowRun、ResolveWorkflowQuestion；428 技能门；`/workflow` 内置命令。
10. **UI 三件**：确认窗时间线、roster（单时钟 reducer 无轮询）、artifacts（先做 file/markdown，图表看板后置）。
11. **通知闭环**：终态 task-notification（errored/stopped 也带回 report 项）、劝阻轮询文案。

**可以最后再做**：进程级 AIMD 治理器与座位闸门（先用引擎 caps 顶住）、因果图第二层投影、workspace 检视器、图表看板。

### 分期建议
- **一期（能跑）**：1-5+9 的 CreateWorkflow/EvalWorkflowSnippet —— 「写脚本→确认→跑→通知」闭环；
- **二期（能救）**：journal 四表+resume+失败策略+quota-resume —— 「停了能续、额度到点自动续」；
- **三期（能修）**：Amend/supersede+导入缓存+FillWorkflowHole —— 「边跑边修零重算」；
- **四期（能存）**：SaveWorkflow/复跑+UI 看板 —— 「鱼皮的完整体验」。
